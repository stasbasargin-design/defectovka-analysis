# Анализ дефектовочной ведомости / АвтоКП

Приватный проект для воспроизводимого анализа дефектовок, тестирования правил подбора авторабот и запасных частей и подготовки изменений в n8n / PostgreSQL.

## Статус

**Этап 0 — проверяемый каркас.** Публикуется код, описание бизнес-правил, тесты и GitHub Actions. Шесть исходных Excel-файлов из исходного пакета должны быть дополнительно загружены в `data/raw/` (см. `docs/github-setup.md`); до их появления тесты на эти данные не выполняются в GitHub. Локально исходный ZIP-пакет со всеми шестью файлами прошёл **11 тестов из 11**.

**Важно:** действующий workflow n8n, реальный контракт JSON 1С и конфигурация боевого PostgreSQL в этот репозиторий пока не перенесены. Базовые тесты не доказывают корректность реального AI-подбора.

## Структура

- `data/manifest.json` — имена, размеры и SHA-256 исходных шести файлов.
- `data/raw/` — исходные выгрузки XLSX (дозагрузка владельцем).
- `src/defectovka/` — отдельные детерминированные правила (не боевой обработчик).
- `tests/` — проверки правил и структуры источников.
- `scripts/audit_sources.py` — неразрушающий аудит связей и остатков.
- `.github/workflows/ci.yml` — тесты при push, PR и ручном запуске.
- `docs/rules.md` и `docs/roadmap.md` — требования и план.

## Локальные проверки

```bash
python -m unittest discover -s tests -v
python scripts/audit_sources.py
```

Нужна только стандартная библиотека Python. При отсутствии `data/raw/` сначала скопируйте исходные шесть Excel из подготовленного архива.

## Безопасность

Репозиторий должен оставаться **private**, так как исходники содержат цены, остатки, автомобили и коммерческие документы. Не публиковать токены API, credentials n8n, пароли PostgreSQL, реальные персональные данные заказ-нарядов.

Рабочие 1С, PostgreSQL, n8n и сайт не подключаются к CI и не изменяются автоматически. Разработка: отдельная ветка → Pull Request → тесты → проверка → ручное согласование переноса.
